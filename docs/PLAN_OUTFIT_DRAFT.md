# План реализации черновика полного образа

## Цель

Сделать применение трансмогрификации ближе к retail-интерфейсу: игрок выбирает
внешности для нескольких слотов, видит общий результат на модели и применяет
весь образ одной кнопкой.

## Пользовательский сценарий

1. Игрок открывает окно у NPC-трансмогрификатора.
2. Выбирает слот и внешний вид.
3. Выбранный вариант сразу добавляется в черновик и отображается на модели.
4. Игрок переходит между слотами и продолжает собирать образ. Уже изменённые в
   черновике слоты имеют отдельную подсветку.
5. Интерфейс показывает количество изменений и общую стоимость.
6. Кнопка `Применить образ` отправляет весь черновик одним запросом.
7. Сервер сначала проверяет весь набор, стоимость и токены. Только после полной
   успешной проверки выполняется списание и применение.
8. `Отменить изменения` очищает черновик и возвращает модель к текущему облику
   персонажа.

## Состояния интерфейса

- Золотистый пульсирующий ореол: облик уже применён на персонаже.
- Голубая рамка и маркер: слот изменён в текущем черновике.
- Золотая рамка элемента коллекции: вариант выбран для активного слота.
- Кнопка применения отключена, если черновик пуст.
- Во время серверного запроса все изменяющие состояние кнопки заблокированы.

## Клиентская модель данных

В аддоне хранится таблица `draftSlots`:

```lua
draftSlots[slot] = itemEntry
```

Дополнительно хранятся:

- `slotPrices[slot]` — стоимость изменения слота из последнего ответа `PAGE`;
- `transmogSlots[slot]` — внешний вид, уже применённый на сервере;
- `selectedSlot` — активный слот коллекции;
- `selectedEntry` — вариант, выбранный для активного слота.

Черновик живёт только пока открыто окно аддона. Закрытие окна или кнопка отмены
очищают его.

## Протокол

Версия протокола повышается до `3`.

Новая клиентская команда:

```text
APPLY_OUTFIT\t<requestId>\t<sessionId>\t<slot:itemEntry,...>
```

Успешный ответ:

```text
RESULT\t<requestId>\tOK\tOUTFIT\t<count>\t<money>
```

Ошибки используют существующий формат `RESULT ... ERROR ...`.

## Серверная проверка

До изменения персонажа сервер обязан проверить:

- активную сессию NPC;
- отсутствие повторяющихся и недопустимых слотов;
- наличие экипированного предмета в каждом слоте;
- наличие каждой внешности в коллекции аккаунта;
- совместимость внешности с целевым предметом;
- достаточное количество денег для всего образа;
- достаточное количество токенов для всего образа;
- ограничение частоты операций.

После полной проверки сервер один раз списывает общую стоимость и токены, затем
применяет подготовленные изменения без повторного списания.

## Проверка

- Выбрать внешности минимум для трёх слотов и убедиться, что модель сохраняет
  весь черновик при переключении слотов.
- Проверить очистку черновика без изменения персонажа.
- Проверить применение при точном количестве денег и токенов.
- Проверить, что недостаток денег или токенов не применяет ни один слот.
- Проверить повторный запрос с тем же `requestId`.
- Проверить смену экипировки перед отправкой образа.
- Проверить русскую и английскую локализации на клиенте 3.3.5a HD.
